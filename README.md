# Git Secret Hunter

Высокоскоростной инструмент аудита истории Git-репозиториев для выявления утечек API-ключей нейросетей, облачных токенов, приватных ключей и случайных секретов с высокой энтропией Шеннона. Оснащен интерактивным TUI-интерфейсом, оконным GUI для Windows и модулем автоматического краулинга GitHub.

[![Release](https://img.shields.io/github/v/release/kirillsql1kaa11/Git-Secret-Hunter?style=flat-square)](https://github.com/kirillsql1kaa11/Git-Secret-Hunter/releases)

[![Rust](https://img.shields.io/badge/rust-2024-orange?style=flat-square)](Cargo.toml)

## Возможности

- **Анализ полной истории Git:** сканирование всех веток (`--all`), тегов, reflog и висячих объектов (dangling commits).
- **Дифференциальный поиск:** анализ исключительно добавленных строк (`diff -U0`), исключая повторные проверки неизмененного кода.
- **Merge-коммиты:** секреты, попавшие в разрешение конфликтов при слиянии, больше не теряются (`--diff-merges=first-parent` с автоматическим фолбэком).
- **Многопоточная обработка:** параллельное сканирование коммитов на пуле потоков Rayon.
- **Группировка находок:** один и тот же секрет, встречающийся в нескольких коммитах и файлах, показывается одной записью с полным списком вхождений.
- **Семейства токенов:** hex, Base64, alnum и dotted-токены анализируются раздельно, что исключает пропуск hex-секретов (GitHub PAT, DeepSeek, произвольные `api_key=<32 hex>`) и мусорных срабатываний.
- **Извлечение кандидатов по regex:** секреты находятся внутри URL-параметров (`?api_key=...`), JSON-строк (`{"token": "..."}`) и в кавычках любого вида.
- **Структурная валидация:** подавление Git-хэшей, UUID, контрольных сумм (`sha256:...`), SRI-хэшей, фикстур, mock-данных и файлов-заглушек.
- **Политика серьёзности:** тестовые и publishable-ключи Stripe получают уровень `LOW`/`INFO` и не ломают CI.
- **Защита от «тяжёлых» репозиториев:** лимиты на длину строки и суммарный размер файла с подсчётом пропущенного.
- **Честные ошибки:** не-git каталог и репозиторий без коммитов завершаются кодом `2`, а не ложным `SUCCESS`.
- **Live-проверка ключей (`--verify`):** найденные ключи опционально проверяются в API провайдеров (OpenAI, Anthropic, GitHub, GitLab, Slack, Stripe, Groq, DeepSeek и др.); в отчёте появляется статус `verified` / `invalid` / `unknown` / `error`. Сами секреты никогда не пишутся в отчёт.
- **Многострочные секреты:** PEM-блоки получают отпечаток по телу ключа (разные ключи больше не схлопываются в один), а YAML-блоки `|`/`>` и TOML-строки `"""`/`'''` склеиваются перед анализом — секрет, разорванный на строки, теперь находится.
- **Отсев мусорных источников:** расширенный список lockfile'ов, отпечатки в манифестах (`sha256sum`), отключение энтропийного поиска в минифицированных однострочных бандлах (правила провайдеров там продолжают работать).
- **Пробелы в Git:** дополнительно сканируются git notes (`--notes`), инициализированные субмодули (`--submodules`) и локальные объекты Git LFS (`--lfs`).
- **Инкрементальный скан:** `--incremental` сканирует только коммиты, появившиеся после последнего прогона; для явного контроля есть `--range`, `--since` и `--until`.
- **Умная выборка краулера:** фильтры по звёздам, размеру, языку и свежести пуша (`--min-stars`, `--max-size-mb`, `--language`, `--pushed-days`), отсев форков и архивных репозиториев по умолчанию, а также дедупликация уже просканированных репозиториев между запусками.
- **Интерактивный TUI-инспектор:** терминальный интерфейс на базе Ratatui с прокруткой, сохранением статуса «устранено» между запусками и корректным восстановлением терминала.
- **Оконный GUI (Windows):** нативный интерфейс на `eframe`/`egui` с массовым краулингом случайных репозиториев, живым прогрессом, фильтрами и экспортом отчёта.
- **Автономный GitHub-краулер:** массовый поиск и аудит публичных репозиториев с настраиваемой параллельностью (`--crawl-concurrency`).
- **Интеграция с CI/CD:** структурированный JSON (`schema_version: 2`) и ненулевой код возврата при блокирующих находках.

## Установка и запуск

### Вариант 1. Готовые бинарные файлы (Рекомендуется)

1. Перейдите на страницу [Релизов](https://github.com/kirillsql1kaa11/Git-Secret-Hunter/releases).
2. Скачайте архив для Windows: `git-secret-hunter-v0.4.0-windows-x64.zip`.
3. Распакуйте архив в любую удобную папку. Внутри два файла:
   - `git-secret-hunter.exe` — консольный сканер (CLI + TUI);
   - `git-secret-hunter-gui.exe` — оконное приложение.
4. Запустите нужный файл или проверьте CLI:

```powershell
.\git-secret-hunter.exe --help
```

> **Примечание:** GUI-сборка необязательна — консольный файл полностью самодостаточен.

### Вариант 2. Сборка из исходников

Для сборки требуется компилятор [Rust](https://rustup.rs/) (версия 1.85+; проект использует edition 2024):

```bash
git clone https://github.com/kirillsql1kaa11/Git-Secret-Hunter.git
cd Git-Secret-Hunter
cargo build --release
```

Для сборки оконной версии дополнительно:

```bash
cargo build --release --features gui --bin git-secret-hunter-gui
```

Готовые файлы: `target/release/git-secret-hunter.exe` и `target/release/git-secret-hunter-gui.exe`.

## Примеры использования

### Быстрый аудит текущего репозитория

```powershell
git-secret-hunter
```

### Сканирование определенной папки

```powershell
git-secret-hunter --path C:\Projects\MyRepo
```

### Интерактивный TUI режим

```powershell
git-secret-hunter --path C:\Projects\MyRepo --tui
```

### Оконный GUI

```powershell
.\git-secret-hunter-gui.exe --path C:\Projects\MyRepo
```

### Поиск только ключей нейросетей (AI APIs)

```powershell
git-secret-hunter --ai-only
```

### Проверка перед коммитом (Staged changes)

Идеально подходит для pre-commit хуков:

```powershell
git-secret-hunter --staged
```

### Вывод в формате JSON для автоматизации

```powershell
git-secret-hunter --format json > report.json
```

### Ограничение нагрузки на больших репозиториях

```powershell
git-secret-hunter --max-line-len 4096 --max-file-size 4194304 --max-commits 5000
```

### Live-проверка ключей

Опциональная проверка найденных ключей в API провайдеров. Секреты отправляются только провайдеру и никогда не попадают в отчёт:

```powershell
git-secret-hunter --verify
```

### Инкрементальный скан и диапазоны

```powershell
# только коммиты, появившиеся после прошлого прогона
git-secret-hunter --incremental

# явный диапазон ревизий и даты
git-secret-hunter --range "HEAD~50..HEAD"
git-secret-hunter --since "2026-01-01" --until "2026-06-30"
```

### Дополнительные источники: notes, субмодули, LFS

```powershell
git-secret-hunter --notes --submodules --lfs
```

### Массовый краулер публичных репозиториев GitHub

Аудит 50 случайных репозиториев в 8 потоков:

```powershell
git-secret-hunter --crawl --crawl-limit 50 --crawl-depth 5 --crawl-concurrency 8
```

Краулинг репозиториев по поисковому запросу с умной выборкой (живые, не форки, не архивные, не больше 100 МБ):

```powershell
git-secret-hunter --crawl --query "language:python bot openai" --crawl-limit 20 --min-stars 50 --max-size-mb 100 --pushed-days 90
```

## Управление в TUI режиме

| Клавиша | Действие |
| :--- | :--- |
| `↑` / `k` | Переход к предыдущей записи |
| `↓` / `j` | Переход к следующей записи |
| `PageUp` / `PageDown` | Пролистать список на страницу |
| `Home` / `End` | Первая / последняя запись |
| `Space` / `m` | Переключение статуса (`ACTIVE RISK` / `RESOLVED`) |
| `q` / `Esc` / `Ctrl+C` | Выход из приложения |

Отметка `RESOLVED` сохраняется между запусками в `%APPDATA%\git-secret-hunter\state.json` и разделяется между TUI и GUI. Переопределить путь можно переменной окружения `GSH_STATE_FILE`.

## Оконный GUI

```powershell
.\git-secret-hunter-gui.exe
```

В окне два режима:

**Краулер случайных репозиториев** (открывается по умолчанию) — то, ради чего проект существует:

- пустой запрос = случайная выборка репозиториев GitHub; можно задать свой запрос (`language:python bot openai`);
- количество репозиториев, глубина истории и число потоков настраиваются прямо в окне;
- фильтры выборки: язык, минимум звёзд, максимальный размер, свежесть пуша, а также отсев форков и архивных;
- «не повторять просканированные» — репозитории из прошлых запусков пропускаются (локальная история хранится между запусками);
- «проверять ключи онлайн» — live-проверка найденных ключей прямо в краулере (статус виден в деталях репозитория);
- GitHub-токен необязателен, но повышает лимиты API;
- результаты появляются по мере готовности: имя репозитория, число находок и блокирующих из них;
- кнопка «Остановить» прерывает краулинг, уже найденное сохраняется;
- выбор репозитория показывает его находки и историю вхождений, отметка «устранено» общая с TUI;
- экспорт всего краулинга в JSON.

**Локальный репозиторий**:

- выбор каталога кнопкой или перетаскиванием папки в окно;
- фильтры по уровню серьёзности, поиск по правилу/файлу/коммиту, режим «только активные»;
- панель «Дополнительно»: live-проверка ключей, субмодули, git notes, Git LFS, «только новые коммиты», диапазон ревизий и даты;
- панель деталей: отпечаток, семейство, энтропия, статус онлайн-проверки, история вхождений;
- кнопка «Отметить как устранённое» (общее состояние с TUI);
- экспорт отчёта в JSON.

Проверка без открытия окна (например, в CI):

```powershell
.\git-secret-hunter-gui.exe --selftest --path C:\Projects\MyRepo --out report.json

.\git-secret-hunter-gui.exe --selftest --path C:\Projects\MyRepo --verify --notes --lfs --incremental --out report.json

.\git-secret-hunter-gui.exe --selftest --crawl --crawl-limit 20 --crawl-depth 50 --crawl-concurrency 4 --min-stars 50 --language python --out crawl.json
```

## Политика серьёзности и коды возврата

| Уровень | Что попадает | Блокирует CI |
| :--- | :--- | :--- |
| `CRITICAL` | Приватные ключи, JWT, платежные live-ключи | Да |
| `HIGH` | Ключи AI-сервисов, облачные токены, AWS, GitHub PAT | Да |
| `MEDIUM` | Высокоэнтропийные и hex-подобные секреты | Да |
| `LOW` | Тестовые ключи (`sk_test_...`), находки в тестовых путях | Да |
| `INFO` | Публичные по определению ключи (`pk_live_...`, `pk_test_...`) | Нет |

Код возврата: `0` — находок нет или только `INFO`; `1` — есть блокирующие находки; `2` — ошибка сканирования (не-git каталог, репозиторий без коммитов, сбой git).

## Группировка находок

Каждый уникальный секрет показывается один раз: отпечаток вычисляется как первые 16 hex-символов SHA-256 от значения секрета (сам секрет в отчёт не попадает). Для группы выводятся:

- список вхождений (коммит, автор, дата, файл, строка);
- количество коммитов и файлов;
- первое и последнее появление;
- правило с наибольшей специфичностью, если секрет поймали несколько правил.

## Поддерживаемые сигнатуры

### Ключи AI и языковых моделей
- OpenAI (`sk-proj-...`, `sk-admin-...`, `sk-...`)
- Anthropic Claude (`sk-ant-api03-...`, `sk-ant-admin01-...`)
- Google Gemini / Google AI Studio (`AIzaSy...`)
- DeepSeek API (`sk-[a-f0-9]{32}`)
- Together AI (`[a-f0-9]{64}`)
- Hugging Face Access Tokens (`hf_...`)
- Replicate API (`r8_...`)
- Groq Cloud API (`gsk_...`)
- OpenRouter API (`sk-or-v1-...`)
- Perplexity AI (`pplx-...`)
- Cohere AI API
- Mistral AI API

### Облачные платформы и авторизация
- AWS Access Key ID (`AKIA...`, `ASIA...`)
- GitHub Personal Access Tokens (`ghp_...`, `github_pat_...`)
- GitLab Personal Access Tokens (`glpat-...`)
- JSON Web Tokens (JWT)
- Приватные ключи (RSA, EC, DSA, OPENSSH)
- Slack Bot / User Tokens (`xoxb-...`, `xoxp-...`)
- Stripe Secret Keys (`sk_live_...`, `rk_live_...`, тестовые `sk_test_...` — уровень `LOW`)

### Энтропийный и структурный анализ
- Hex-секреты длиной 32, 40 и 64 символа, включая значения после `api_key=`, `token:`, `secret =`.
- Семейства токенов: `hex`, `base64`, `alnum`, `dotted` — с отдельными порогами энтропии и требованием цифр для alnum-строк.
- Извлечение кандидатов из URL-параметров, JSON, YAML и строк в кавычках.
- Подавление Git-хэшей, UUID, контрольных сумм (`sha256:...`, `md5sum`, SRI), примеров, плейсхолдеров и mock-данных.
- Порог энтропии по умолчанию $H \ge 4.5$ (для hex — $H \ge 3.0$), минимальная длина токена — 24 символа.

## Формат JSON-отчёта

Отчёт (`--format json`) содержит:

- `schema_version` — версия схемы (текущая `2`), `tool_version` — версия инструмента;
- `total_commits_scanned`, `total_diff_lines`, `scan_duration_ms`;
- `skipped_lines`, `skipped_files` — сколько пропущено из-за лимитов;
- `total_findings` — все срабатывания, `unique_findings` — количество уникальных секретов;
- `verified_findings`, `invalid_findings` — сколько ключей подтверждено или отклонено провайдерами (при `--verify`);
- `findings` — плоский список (`rule_id`, `severity`, `confidence`, `fingerprint`, `secret_preview`, `file_path`, ...);
- `groups` — сгруппированные находки с массивом `occurrences` и опциональным блоком `verification` (`status`, `provider`, `detail`).
